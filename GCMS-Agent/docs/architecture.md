# 系统架构与信任边界

[English](architecture.en.md) | **简体中文**

GC–EI–MS Agent 由 Python 宿主控制执行。模型负责读取候选、提出假设和调用受控工具；化学验证、证据枚举、计分、结构提交、预算与停止状态由程序决定。

## 数据流

```text
本地原始数据 → 可信准备程序 → 无标签推理输入 → Python 工作流
                         │                      ├─ 分子图 / 化学验证 / 编辑
                         │                      ├─ 固定 EI 规则 / 评分
                         │                      └─ Harness → Claude SDK/CLI → 模型服务
                         │                                      ↕ 受控 MCP 工具
                         └─ 独立标签 → 运行结束后的独立评估器 ← 保存的预测
```

[数据准备](../src/gcms_agent/data/prepare.py)将源数据拆分为推理输入与标签，记录源哈希、输入哈希及强度编码。[输入加载器](../src/gcms_agent/data/loader.py)只接受白名单字段，拒绝 `true_smiles` 等未知字段。私有数据仅在本地使用；公开的[人工示例](../data/examples/README.zh-CN.md)独立构造，不是实测性能基准。

[运行器](../src/gcms_agent/workflow/runner.py)提供两条主要执行路径：`baseline` 直接验证和评分候选，不调用模型、不编辑结构；`agent` 使用模型工具会话探索候选。不同谱图当前依次处理；同一谱图内先合并等价候选计算，再保留所有原始来源槽位输出。

## 模型与工具边界

[Harness 客户端](../src/gcms_agent/harness/client.py)通过 Claude Agent SDK 与原生 CLI 访问配置中的兼容模型服务。模型名称、思考设置和费用参数见[配置说明](../configs/README.zh-CN.md)；服务返回的型号会被记录，别名不等于不可变的模型权重版本。

SDK 配置禁用默认工具、原生技能自动加载、个人设置来源与会话持久化，仅开放项目注册的 MCP 工具。会话使用独立工作目录和 `CLAUDE_CONFIG_DIR`；这限定了暴露给模型的工具能力，不是操作系统级进程沙箱。

运行入口可从本地 `.env` 加载 `DEEPSEEK_API_KEY`，已有进程环境优先。凭据不进入推理输入、模型上下文或源码版本快照。客户端还递归拒绝真值和凭据类字段。

默认批审工具由 [batch_server.py](../src/gcms_agent/tools/batch_server.py) 注册：

| 工具 | 用途 |
|---|---|
| `get_candidate` | 查询候选紧凑状态或完整图 |
| `get_spectrum` | 查询原始线性峰强及独立的全谱权重 |
| `get_evidence` | 按候选或试验读取完整碎裂证据 |
| `read_reference` | 按注册 ID 读取技能参考，不接受任意文件路径 |
| `analyze_proposals` | 在候选副本上应用编辑、验证并评分，生成试验 ID |
| `submit_reviews` | 引用试验 ID，提交本批全部候选的结构化审阅 |

最终自由文本不作为结构化结果解析。分析工具生成的试验不自动提交为候选状态；正式提交后仍由工作流复核。模型理由与工具证据分别保存，程序没有逐项证明自然语言解释与碎片机制的因果关系。协议详见[编辑与停止](editing_and_stopping.md)。

## 技能、缓存与探索信息

[SkillLibrary](../src/gcms_agent/harness/skill_loader.py)显式加载五份主技能，参考文档以注册 ID 按需提供。运行时提示由[提示构造代码](../src/gcms_agent/harness/prompts.py)与当前技能生成，不依赖导出的静态快照。

模型紧凑视图保留 MoleCode、完整谱峰及对应全谱权重；证据路径使用带列名的行表，重复评分对象通过引用压缩。需要完整路径和原子编号时可调用查询工具。字符压缩不直接等于 token 或费用节省。

同一谱图内的确定性试验可缓存，但原子映射结果绑定精确图及编号。候选自己的历史、最佳图、图版本和试验记录由宿主管理。跨会话的试验 ID 不能直接作为新会话提交依据，必须在当前图上重新分析并注册。

[探索摘要](../src/gcms_agent/workflow/exploration.py)向后续批次提供同一谱图此前已完成批次中的合法结构、支持峰、分数、环信息和来源摘要。最多展示 40 种结构，兼顾高分与近期结构，并记录遗漏数；同一并发批次组中的会话看到相同的先前状态。摘要不转移原子映射或可提交的试验 ID，也不保证模型一定减少重复。

`memory/` 中的独立记忆组件尚未接入默认运行流程。这里的候选历史、试验缓存和同谱探索摘要由工作流实现；不会自动把当前样本猜测或标签写入跨样本知识库。

## 调度、用量与可靠性

默认 Agent 使用 `economy` 配置，同一谱图内最多并行两批；一组并发批次结束后，按固定顺序提交状态并保存检查点。所有候选初审完成后再进入下一轮。致命错误停止新请求，已发送请求仍需保存回执并结算。

[预算账本](../src/gcms_agent/workflow/budget.py)对每个请求结算一次最终用量，不能按候选重复累计共享会话费用。中断且无可靠最终用量时标记未知并保留估算；零用量审计记录不自动意味着服务端零费用。价格来自项目配置快照，不是实时账单。

请求尝试数与有效会话计数分开。只有审计能确认的特定连接错误、已知零用量且无工具或试验执行，才可能豁免有效会话计数；原回执仍保留，另受连接失败上限约束。无回执或未知用量不能据此豁免。判定见[传输错误分类](../src/gcms_agent/harness/transport.py)。

当前基础配置和 economy 均不设默认总金额上限，economy 也不设单谱金额上限；可以显式配置限制。预留金额、生成上限、SDK turn、分析调用次数和候选轮次是不同控制量，见[配置说明](../configs/README.zh-CN.md)。已知输出超限、服务错误或资源结束不应被解释为化学收敛。

## 结果与科学边界

合法结构探索允许同分或降分，当前探索图与历史最佳输出分开保存。非空 `final_smiles` 须满足严格母体约束；证据不足或处理未完成时保留对应状态，见[分子契约](molecode_contract.md)与[评分说明](scoring.md)。

固定规则及技能不会在推理期间由模型自行改写。规则支持分、协议完成状态和结构身份确认是不同概念。未实现的碎裂路径、同位素比例假说或模型确信度不能自行增加分数。

运行会保存输入、配置、源码/技能/规则等指纹。恢复需通过兼容性检查，具体例外与使用方式见[恢复约定](editing_and_stopping.md#resume)。
