# Contract for MoleCode repair graphs and valid outputs

**English** | [简体中文](molecode_contract.md)

Conversion, editing, and validation are implemented in [smiles_io.py](../src/gcms_agent/chemistry/smiles_io.py), [graph_edit.py](../src/gcms_agent/chemistry/graph_edit.py), and [validation.py](../src/gcms_agent/chemistry/validation.py), respectively. The MoleCode adapter is [molecode_adapter.py](../src/gcms_agent/chemistry/molecode_adapter.py).

## Input categories

1. Default RDKit parsing succeeds: construct the graph and continue with project-specific neutrality, connectivity, closed-shell, and fidelity checks.
2. SMILES syntax is parseable but chemical checks fail: extract atoms and connectivity with `sanitize=False` and a permissive property cache to construct a graph awaiting repair. This does not guarantee chemical validity; hydrogen counts and aromatic flags require confirmation.
3. Syntax cannot form a complete graph: automatically remove only unambiguous outer whitespace and a complete code fence containing one SMILES string. Do not guess missing ring numbers, parentheses, or atoms. Record failure as `syntax_unparseable`, with `final_smiles=null`.

Conversion to MoleCode, molecular validity, and spectral support are separate states. The presence of graph text in a file does not establish successful repair.

## Stable structure data

Graph JSON is the machine state:

```text
atoms: id, element, isotope, charge, hydrogens, radicals,
       aromatic, chiral_tag, atom_map
bonds: a, b, order, stereo, stereo_atoms
```

MoleCode presents these structures as nodes and edges. Isotopes appear in atom labels, such as `[13CH3]`; additional `%%@atom` / `%%@bond` metadata preserve radicals, atom maps, and stereochemical references. These machine annotations must not be confused with ordinary explanatory comments or removed arbitrarily. Unknown hydrogen counts must not be filled automatically during export to make a structure valid.

Ordinary single, double, triple, and aromatic bonds can be read. Invalid inputs may retain aromatic bonds as `<-->`; valid structures may be displayed in Kekulé form. Edits use stable atom IDs. Canonical SMILES reordering is not used to reconstruct historical atom identities.

## Stereochemical compatibility

The project uses the `gcms-molecode-1` small-molecule subset and does not implement all upstream MoleCode syntax.

- When importing stereochemical SMILES, tetrahedral configuration is stored in the `chiral_tag` field of `%%@atom` metadata and maintained together with atom and edge ordering. This is an RDKit relative-order tag, not an absolute R/S label. R or S must not be mapped directly to an integer.
- Upstream absolute CIP suffixes `_R` / `_S` written directly on atom IDs cannot currently be restored. Both parsing and graph validation explicitly reject them, even when `chiral_tag` is also supplied. They are not treated as ordinary IDs and exported as SMILES with lost configuration. Use the project converter on SMILES containing `@` / `@@` to obtain a complete graph and metadata.
- Double-bond `===|E|` / `===|Z|` labels require consistent `%%@bond` metadata containing `stereo` and two ordered `stereo_atoms` reference IDs. Bare E/Z labels, conflicting labels and metadata, and missing reference atoms are rejected. E/Z graphs generated by the project SMILES converter support faithful round trips; handwritten metadata must still pass strict structural validation.
- The current editing API cannot reassign tetrahedral configuration. Edits affecting the connectivity or hydrogen count of a marked center are rejected. When the same neighboring bond is merely removed and re-added, the relative tag is adjusted for neighbor order to preserve the original configuration.
- Unsupported stereochemical types, polymers, and Markush syntax cannot be used as final molecular-graph inputs. Unspecified stereochemistry remains unspecified; spectrum scoring does not automatically assign a configuration.

## Editing and validation

Allowed operations are `set_bond`, `remove_bond`, and `set_atom`. The last operation modifies only hydrogen counts, charge, radicals, and aromatic flags. Heavy-atom addition, deletion, and element replacement are disallowed. The number of operations has no fixed upper limit. The complete operation group is applied to a copy and checked as a whole afterward.

Strict output validation requires:

- Valid node and edge syntax, unique IDs, and no dangling edges or self-loops.
- Heavy-atom composition matching the initial graph, with a neutral, connected, closed-shell parent molecule.
- Complete RDKit sanitization without silently changing hydrogen counts or radical states.
- A positive mass for each explicit isotope in the current RDKit isotope-mass table. Unknown isotopes may remain in graphs awaiting repair but are rejected for final output and mass calculation; they cannot fall back to ordinary elemental mass.
- Exported SMILES that can be strictly parsed again with matching structure and molecular formula.
- MoleCode round trips that preserve atom/bond properties and molecular identity.

Fragment radicals are not subject to the parent's closed-shell constraint; they are accounted for in separate fragment-evidence structures. Edits requiring reassignment of tetrahedral stereocenter connectivity are currently unsupported and explicitly rejected. The tool does not remove stereochemical markers to make such edits pass.

## Output invariants

A nonempty `final_smiles` must pass every final check. Inputs that cannot be repaired remain among the ten source records, but invalid strings are not emitted as final molecules. Output validity and repair success are reported separately: failure to repair within the budget does not permit invalid output.

## Independent ion and product validation

[ion_validation.py](../src/gcms_agent/fragmentation/ion_validation.py) provides independent checks for fragment hypotheses without changing the parent's neutrality, connectivity, and closed-shell requirements.

- `validate_fragment_ion` checks ion-graph connectivity, valence, hydrogen/radical fidelity, charge and electron parity, and SMILES/MoleCode round trips.
- `validate_fragment_products` checks ion and neutral product graphs after single ionization, parent atom-ID allocation, element/isotope and hydrogen conservation, and declared bond changes against actual graph changes.

Stable IDs express a declared correspondence between graphs; they do not establish actual reaction atom trajectories. Implicit-hydrogen changes express only net changes. Isotopic hydrogen must be retained as an explicit atom. The validator does not invent atom mappings for missing products or promote stoichiometric feasibility to experimental confirmation of a mechanism.

Validation results do not automatically register a formal scoring rule. Current scoring channels and limitations are described in the [scoring contract](scoring.en.md) and [rule conditions](../resources/ei_rules/CONDITIONS.md).
